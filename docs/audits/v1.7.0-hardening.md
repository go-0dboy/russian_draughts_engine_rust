# CODE REVIEW — v1.7.0 production hardening

## Scope

v1.7.0 специально построена от accepted v1.5.1, а не от экспериментальной ветки v1.6.x.

Не включены:

- staged MovePicker v1.6.x;
- новая LMR policy;
- новые pruning heuristics;
- изменение HCE;
- изменение production SearchParams.

## Исправленные подтверждённые проблемы

### 1. Блокирующий protocol read

Раньше `Engine._read()` вызывал `stdout.readline()` без timeout. Это делало бесполезным последующий `wait(timeout=2)`: `close()` мог никогда до него не дойти.

Теперь stdout читается как бинарный fd через `selectors` + `os.read` с собственным line buffer. Timeout действует и на полностью молчащий процесс, и на процесс, который вывел только часть строки.

### 2. Shutdown child process

`close()` больше не вызывает `cmd("quit")` и не ждёт `bye`.

Последовательность:

```text
send quit
→ bounded wait
→ terminate
→ bounded wait
→ kill
```

Это делает завершение независимым от корректности протокольного ответа child process.

### 3. stderr deadlock

Раньше `stderr=PIPE` нигде не читался. Достаточный объём stderr мог заполнить pipe и заблокировать движок.

Теперь stderr направляется во временный файл. После аварийного завершения его хвост можно использовать в диагностике, но pipe backpressure отсутствует.

### 4. Cleanup workers/executor

- `PairWorker` закрывает A, если запуск B завершился ошибкой;
- частично созданный список workers очищается;
- при исключении/KeyboardInterrupt активные futures отменяются;
- child engines закрываются до ожидания executor threads, чтобы заблокированный protocol call получил EOF/termination;
- SPSA использует один executor на итерацию вместо создания нового на каждый batch.

### 5. Lost-stop race

Старый код делал `self.control.clear()` в начале `search()`. Stop, отправленный после создания control handle, но непосредственно до выполнения этой строки, терялся.

Новый control использует монотонный `AtomicU64` sequence. `request_stop()` увеличивает sequence; search сравнивает его с последним потреблённым значением. Наблюдённый `ExternalStop` потребляется один раз, поэтому следующий search не наследует уже обработанный сигнал.

### 6. Terminal precedence

`Game::status_with_legal_count(0)` правильно отдаёт loss by immobility, но ранний negamax fast path мог вернуть automatic draw/adjudication до генерации ходов.

Теперь только для уже сработавшего automatic draw/adjudication выполняется точная проверка legal moves. Это редкий путь и не меняет normal TT fast path. При `legal_count == 0` loss by immobility имеет приоритет.

## Packaging limitation

В packaging environment Rust toolchain отсутствует, поэтому Rust-код не объявляется исполнительно проверенным здесь. Python hardening regressions, `py_compile`, shell syntax, manifest/checksums и updater проверяются при упаковке. Полный cargo gate выполняется на пользовательском Termux host до принятия v1.7.0 как baseline.
